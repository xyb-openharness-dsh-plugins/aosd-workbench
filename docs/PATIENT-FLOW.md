# 患者与家属任务流（M0 草案）

状态：🔧 待 G1；0 访谈，不代表真实患者流程已经验证。服务主体“患者及家属”已由用户于 2026-10-27 明确。

## 三条候选任务链

| 任务 | 开始时的整理困难（假设） | 患者/家属动作 | 可观察产物 | 不做什么 |
| --- | --- | --- | --- | --- |
| 一次就诊前准备 | 日期、报告和想问的问题散在不同地方 | 选择已确认记录 → 查看缺项 → 编辑自己的待问事项 → 导出 → 回看 | 一份带来源、记录者与未决问题的就诊材料 | 不替医生给诊断或安排处置 |
| 一次症状或代记补充 | 患者不便记录时，家属的描述可能与本人感受混在一起 | 选择本人/家属代记 → 记录日期与原话 → 核对 → 保存 → 同日回看 | 一条可区分记录者、可追加更正的自述记录 | 不从症状推导疾病名、活动度或风险 |
| 一次报告归档与复查回顾 | 报告数值、单位、参考范围和检查日期需要保留 | 手工或显式云解析 → 逐项核对候选 → 入库 → 查看报告/指标与就诊材料 | 报告原件索引与确认指标；可比序列 | 不将识别值自动当事实；不跨机构强行比较 |

## 反推页面而不是照搬医生流程

- 看板只回答“最近记了什么、哪些待核对、复诊前准备到哪一步”，不展示自动病情判断。
- 时间线服务于还原经过；指标服务于查找原报告与同口径序列；两者并列但不互作解释。
- 就诊准备是导出与回顾的闭环；AI 只是可选整理入口，不能让无会话时无法记录。
- 设置单独管理资料目录、云解析授权与私密边界；未指定资料目录时不是“已连接”。

## 待 G1 决定

1. 一期是否把“同日多轨 + 代记来源 + 就诊材料”作为最小闭环，其他场景二期展开。
2. 未确诊前的资料归档如何与已确诊档案隔离，避免病名先行。
3. 患者与家属在同一设备上的查看/编辑边界；默认不假设共享账号等于双方同意所有内容公开。
