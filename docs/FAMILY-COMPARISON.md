# AOSD 与 cervical / breast 家族对比及一级页面候选

状态：M1 独立研究候选，未签 G1/G2/G3；本次不改 SPEC、不改生产 SCHEMA/API。日期：2026-10-27。研究分支：`research/family`。

> **后续范围修订（2026-10-27）：** 本文的指标可比序列、多指标时间视图与曲线验收是历史候选，已由独立患者评审后的“一期原报告值/单位/采样与报告日期/来源表”替代。保留原文用于研究追踪，不得据本文恢复一期图形；重名率只比较页面名，不决定功能是否保留。现行范围以 SPEC/INTERACTION-DESIGN/UI-DESIGN 为准。

## 0. 结论与证据边界

- 建议以 **8 个一级页**进入 G1 讨论：`看板 / 本人与代记 / 同日经过 / 报告与核对 / 指标回看 / 用药与医嘱 / 复诊准备 / 疾病与资源`。它们是待患者及家属核对的信息架构，不是已确认需求，更不是已实现页面。
- 逐字重名率实测：对 cervical 为 **2/8 = 25%**；对 breast 为 **1/8 = 12.5%**。主口径分母均为本次候选数 8，均低于 70% 目标。补充口径见 §4。
- 核对到 cervical 原型实际 **12 个一级页**、breast 原型实际 **8 个一级页**。`病情整理` 是二者原型的一级显示名，`资料库` 是其二级页，不能误计为两个一级页。
- AOSD 已确认的服务主体是患者及家属；真实访谈 0、临床审核 0。页面优先级、代记权限、同日多轨是否应进入一期，仍须访谈和 G1 签认。本次没有声称患者价值已验证，也没有以“不同于癌症”代替价值证明。
- **共享的是工程合同，不是肿瘤患者需求。** 可复用 DSH 宿主适配、原件/候选/已确认事实分层、统一读模型、修订链、私密过滤、MinerU 知情与失败语义、结构化 API 错误。不得搬入 FIGO/TNM/其他肿瘤分期、CTCAE、治疗线/周期、肿瘤负荷/终点、复发概率或肿瘤试验匹配逻辑。
- 本次只读两个基准仓并抽取源码数组重算重名率；未做浏览器验收、真实 Desktop 验收、生产 API 联调或云端 MinerU 调用。完整证据、快照和复算脚本见 [family-evidence.md](../research/aosd/family-evidence.md)。

### 2.2 已发现“不能原样复用”的实现差异

1. **缺单位不能由字典补造。** cervical `dsh/import.js:132-143` 在单位缺失时采用 `unitCell || hit.unit`；AOSD 当前合同要求未知单位留空并标缺单位，见 `docs/18-MINERU-PARSING.md:270-288` 和 `docs/DEV-REQUIREMENTS-2026-10-27.md:34-38`。可以复用对齐与候选机制，不能复用这个默认值。AOSD 自己的 `docs/SCHEMA.md:1-14` 和 `docs/API-CONTRACT.md:1-12` 仍是模板，未授权建表或实现。
2. **breast 的 MinerU 模型顺序不是 AOSD 当前合同。** breast `docs/MINERU.md:112-131` 默认 vlm、受控退回 pipeline；AOSD `docs/18-MINERU-PARSING.md:9-20,66-70` 默认 pipeline、仅在接口明确拒绝参数时退回 vlm，并保留各自识别局限。采用 AOSD 现行文档，不宣称某一模型对真实 AOSD 报告已验证。
3. **breast 已有照护者来源，不应宣称 AOSD 从零首创。** 其 `docs/SCHEMA-SPEC.md:163-195,350-392` 已有 `caregiver_reported`、`speaker_role`、`subject_role` 等字段。AOSD 的候选增量是把“谁记录、与患者什么关系、原话、患者补充/确认、发生/录入时间”作为同日多轨与三个出口的通用约束，权限仍待家属和患者验证。
4. **breast 症状 0–3、乳腺提醒和 CTCAE 路由不移植。** 其 `docs/SCHEMA-SPEC.md:350-362` 的 0–3 是本项目主观强度设计，`docs/DATA-FLOW-SPEC.md:115-129` 的 2cm 是乳腺提醒口径，`dsh/server.js:299-324` 是 CTCAE 参考文件出口；均不得变成 AOSD 活动度、阈值、诊断或处置规则。AOSD `docs/METRIC-GRADING.md:1-16` 明确当前不启用分级、不生成活动度/复发/疗效。
5. **API 路径和错误外形按目标合同实现，不能拼接旧习惯。** breast 当前采用业务 `/api/*`、宿主基址另加且 `apiBase` 不重复 `/api`，见 `dsh/server.js:190-217`；cervical 使用 `/api/cervical/*`，见 `dsh/routes.js:11-12,66-100`。AOSD 先落实自身 `docs/API-CONTRACT.md` 与 `docs/DEV-REQUIREMENTS-2026-10-27.md:51-60` 的版本化、鉴权、结构化错误和调用约定，不能在 G3 前假定最终路径或冻结表结构。

### 2.3 禁止进入 AOSD 的肿瘤模型

不得设置肿瘤分期/分型推导、FIGO/TNM、治疗线/线序/周期、CTCAE 默认分级、肿瘤负荷或终点、复发/进展风险、疗效归因、肿瘤试验资格评分。不能仅把癌种名换成 AOSD 后保留相同页面、指标字典、阈值或演示档案。药物、就诊和研究登记只允许作为带来源的事实或公共线索，不自动解释为治疗推荐或个人入组资格。

## 4. 逐字重名率实测

### 4.1 主口径（用于判定 ≤70%）

设 `A` 为上述 8 个候选显示名，`B` 为指定基准原型 `PAGES` 的全部显示名。只比较一级 label，按 JavaScript `String.prototype.includes` 做**大小写敏感、Unicode 码点逐字相等**判断。不去空格、不繁简转换、不拆分、不去标点、不做同义词或语义归一。每项按基准内是否出现计一次，不按两个基准重复出现的次数加权。

`R(A,B) = |{ a ∈ A : a ∈ B }| / |A| × 100%`

- **cervical：** `|A| = 8`，`|B| = 12`，交集为 `{看板, 复诊准备}`，所以 **2 ÷ 8 × 100% = 25.00%**，目标 ≤70%，通过。
- **breast：** `|A| = 8`，`|B| = 8`，交集为 `{看板}`，所以 **1 ÷ 8 × 100% = 12.50%**，目标 ≤70%，通过。

| 候选名 | cervical 同名 | breast 同名 |
| --- | --- | --- |
| 看板 | 是 | 是 |
| 本人与代记 | 否 | 否 |
| 同日经过 | 否 | 否 |
| 报告与核对 | 否 | 否 |
| 指标回看 | 否 | 否 |
| 用药与医嘱 | 否 | 否 |
| 复诊准备 | 是 | 否 |
| 疾病与资源 | 否 | 否 |
| **重名项 / 候选分母 / 比率** | **2 / 8 / 25.00%** | **1 / 8 / 12.50%** |

### 4.2 补充口径与解释边界

为避免把“分母”藏起来，同时报告基准侧覆盖率 `C(A,B) = |A ∩ B| / |B|`：cervical **2/12 = 16.67%**，breast **1/8 = 12.50%**。它回答“基准一级页有多少被候选逐字复用”，不是本次 ≤70% 目标的判定口径。二者交集相同，不能相加后除以 20 来替代任一基准的独立判定。

重名率只测名称，不测功能质量；改名不会使复制肿瘤需求合法，也不能证明同日多轨或代记有患者价值。后续如改页面名，须固定候选集合后重新运行 `research/aosd/family-evidence.md` §6 的脚本，并记录原型 hash 与结果。没有另造“语义相似率”来粉饰或夸大差异。

| F03 | **同日多轨经过**：选择某日，并列自述、就诊/报告、用药事件、医生答复；发生日与录入日分开 | 同日仅表达时间共现，不推药物疗效或因果；不把来源合并成一句“病情总结” | 构造同日 4 轨、跨日 1 轨及后补录 1 条；日期筛选、来源筛选和详情回源正确；后补录不改变发生日；页面无因果、治疗线、周期或活动度字段。 |
| F04 | **报告候选核对**：手工或显式 MinerU 解析，逐项接受/修改/拒收；失败可重试或手录 | 知情同意外发；密钥不明文；表格先转竖线表；不等式原文保留，未知单位/日期为 null；拒收零副作用 | 覆盖无 Token、拒绝授权、失败、成功 0 候选、单位缺失、`<0.5`、表格数量不符；失败不产候选且原件在；缺单位不得由字典补；接受后 `reviewed_by` 不伪装临床审核。 |
| F05 | **可比指标与同日感受并置**：不同单位/方法/机构拆组，点详情回原报告；自述不进入数值曲线 | 每条线全期归一化、不可比说明、单点不连线、空窗口空态；不启用 CTCAE 或 ×ULN 猜测 | 缺单位、单位变化、机构/方法变化、单点、空窗逐一走查；指标、卡片、同日、导出同源；全文无活动度、复发、疗效归因和默认分级。 |
| F06 | **用药与医生答复留痕**：追加开始/变更事件及医嘱原文，患者理解独立，旧版本可追溯 | 药名和剂量按原文；未知不推断；实际事件不由待办完成自动产生；不输出停换药建议 | 新增版本后旧版仍可查，跨页最新版本一致，旧导出标过时；同日显示只说明共现；文案搜索无调药、停药、治疗线/周期生成。 |
| F07 | **复诊材料与快照**：用户选择记录和问题，导出真实文件；后来更正能提示旧快照过时 | 三个出口私密过滤；记录者、来源、数据截止、生成时间分开；不静默重写历史导出 | 导出文件可打开且仅含选入项；本人/代记/报告/医生答复分区可追；默认私密内容不在读模型、导出、AI 草稿；更正后旧快照标过时而非消失。 |
| F08 | **疾病与公共资源分层**：概要、指南、登记、公开叙述分别标来源/版本/局限 | 概要只解释公共事实；登记不是入组资格，公开叙述不是患者总体比例；未确诊档案不自动归病 | 原件/入口页类型和日期可见，失效与未核实如实显示；从公共线索可加入待问事项但不生成资格/推荐；资料切到未确诊范围不出现 AOSD 结论。 |
| F09 | **共享工程防线**：宿主/独立服务一致；稳定 ID、revision、统一读模型；结构化错误；原生 Agent 右栏 | 页面不是事实表；候选/AI 输出需确认；宿主鉴权不能因 loopback 跳过；手录与回看无 AI 也可用 | 未知接口 404、未选工作区 409、坏 JSON 400；跨页读写同源；修订/重试/并发可恢复；source/origin 校验与私密过滤通过；真实 Desktop 另行验收，源码检查不能替代。 |

## 6. 进入 G1 前仍需回答的问题

1. 患者与家属是否把“同日多轨 + 代记来源 + 就诊材料”排在其他任务之前？8 个入口是否过多，哪些名称符合他们的语言？
2. 谁可以代记、修改、确认或查看哪类内容？患者确认是必要条件还是可选补充？共享设备下如何退出和再次验证？未签前不能推定完整权限模型。
3. 未确诊、已确诊和其他医疗资料如何隔离且不丢失历史？哪些用药/就诊字段足够低负担，不能从癌症原型继承？
4. 需要哪些 AOSD 报告字段与可比组？只有取得相应原件和医学核对后才讨论医学阈值；不得为了填页面启用 CTCAE、活动度、治疗线或固定随访节奏。
5. 候选通过后，按 HTML 原型先行→真实预览与签认→复核 SCHEMA/API→实现与验收的顺序推进。本次研究不授权生产建表、后端业务开发或将候选标为已交付。
