# 成人斯蒂尔病工作台规格 v0.1（G1 待签）

日期：2026-10-27。服务对象**患者及家属已确认**；本规格其余范围待 G1 签认。0 访谈、0 临床审核，公开资料不等于患者验证。依据：[SCENARIOS](SCENARIOS.md)、[USER-RESEARCH](USER-RESEARCH.md)、[FAMILY-COMPARISON](FAMILY-COMPARISON.md)、[INTERACTION-DESIGN](INTERACTION-DESIGN.md)。

## 1. 问题与最小闭环

患者或家属把一次感受、代记、报告、用药/医嘱按日期和来源保存，复诊前选材、写问题、导出并回看。输入可手工，也可在用户明确选择后由 AI/MinerU 生成候选；候选必须逐项核对。输出是带来源的记录与就诊材料，不是诊断、病情评分或处置方案。

**完成定义**：真实 Desktop 中，无 AI 会话也能手录、保存、回看和导出；有 AI 时，只把用户明确选择的上下文送入原生会话，回复不自动入事实。当前未实现，V1/V2/V3 均未通过。

## 2. 范围与明确不做

一期候选：8 个一级页（见 §4），S01–S08，低负担手工记录、本人/代记来源、同日四轨、报告核对、可比指标、用药/医嘱版本、就诊快照、公共资料与本地指南。

不做：症状测病/Yamaguchi 自测、分型/活动度/复发或 MAS 风险计算、诊断/处置/调药、疗效归因、CTCAE 默认分级、癌症分期/治疗线/周期、心理诊断、自动复查频率、中国费用/报销推断、多人家庭账号默认互见、虚构试验登记或个人入组结论。

## 5. 数据与 API 候选合同

### 5.1 稳定领域关系

- `subject`：一位患者主体，含病名记录状态（未确诊/医生记录的病名），不计算诊断。
- `source_actor`：本人/家属/报告机构/医生/AI 等来源身份与关系；AI 不是医学审核者。
- `document`：原件索引、hash、MIME、机构、报告日期、存储相对位置；公共指南与患者文件分根。
- `narrative`：本人/代记原话、生活影响、发生与录入时间、授权、私密与确认状态。
- `medication_event` / `clinical_reply`：计划与实际分开、药名和剂量原文、医生原话与患者理解分栏。
- `candidate`：AI/MinerU 抽取及逐项核对状态；接受后形成记录，不变成医学审核。
- `observation` + `metric_definition`：原文值/可空数值/单位/参考范围/方法/机构/日期；可比性拆组。
- `question`、`visit_snapshot`：用户问题、已选事实 ID、数据截止、生成时间、导出与过时状态。
- `public_resource`：公共资料版本、URL/本地路径、来源性质、核实状态与局限，与患者事实分离。

所有可更正记录含稳定 ID、revision、supersedes 来源与创建时间；更正新增版本，旧版保留。候选/事实/指标/文档不合并。强制禁止 `diagnosis/risk_level/eligible/suitability` 判读列；复合主键裸查询 `ORDER BY rowid`，可空显式 null，`in_use` 替代保留字，分节标题独立，分类不进入数值趋势。

### 5.2 API 初稿（G3 前不冻结）

- 已有骨架：`GET /api/aosd/health`，宿主鉴权，不跳过 loopback。
- 计划读模型：`GET /api/aosd/bootstrap`、`GET /api/aosd/day?date=…`、`GET /api/aosd/metrics`、`GET /api/aosd/visit-prep`。
- 计划命令：自述/代记/文档/指标/用药/医嘱/问题的 create+correct、候选 accept/reject、快照 export。
- 公共文件：`GET /assets/guidebooks/nhc-86-rare-diseases-2025.pdf`，白名单常量映射、拒绝 `..`，返回 PDF content-type 与哈希可核。
- `apiBase` 不含 `/api`，调用写 `${apiBase}/api/aosd/...`；独立与嵌入同源路由。400 输入、404 未知、409 未选目录/修订冲突、413 文件过大、502 外部不可用、503 能力未配置，统一结构化 `{error:{code,message,retryable,details?}}`，不向页面裸 throw 或泄露堆栈/密钥。
- 写入 revision/幂等/事务；AI 消息 `aosd:agent-draft` 校验 origin+source，≤8000，按 34 号发送/降级，private 三出口默认排除。

## 6. 设置与隐私

设置常驻顶栏，患者资料目录与公共参考数据分区。目录必须用户明确指定；拒绝主目录、桌面、下载根、tmp，取消无副作用，不重置旧库。M0 未指定资料目录。

MinerU 显示所选文件、接收方、目的与限制，按文件/批次主动授权；Token 文件优先、只回显来源/掩码，云端失败保留原件且不产候选。数据、导出、AI 草稿三出口 fail-closed；本人授权不等于默认分享所有私密，代记不自动获得全部权限。

## 7. UI、原型与一致性

原型为唯一视觉合同，四件套 file:// 可开，开发版逐字符；2 套合成档案仅用于展示来源/空态/补充，不冒充真实病例。3 个品牌变量之外偏差需记录签认。

字号 12.5–15、页脚贴底、`[hidden]`、面板 25–45% 可拖可收、SVG 根 `class="chart"`、Fritsch–Carlson 单调曲线、分类不连线；长内容整页、返回/关闭双入口、滚动/焦点/history/Esc 按 32 号。

疾病概要四段与 README 同源；本地指南与官方链接可点。折叠卡以“就诊/用药事件概要→细节”使用，默认收起，打印展开实测，不照搬肿瘤治疗线五块。状态卡以“记录起点/待初始化”为空态，不伪造 D+N。
